# Day2：员工身份与商户入口

2026-11-05，Asia/Shanghai。核心代码、自动化检查与正式沙盒部署已完成；真实设备签名及外部通道依赖仍待验收。

## 本日范围

正式代码位于 `v1.0/apps/api` 与 `v1.0/apps/web`，使用独立依赖、构建产物和 `kaloq_v1_` 数据库命名空间。正式迁移唯一版本源为 `v1.0/database/migrations`。本日只建立员工身份、商户资料基础与签名技术验证，不建立资金表或执行通道资金动作。

- 密码通过后仅有受限挑战；员工必须绑定 TOTP 才能访问业务。
- TOTP 秘密加密存储，恢复码只保存哈希。恢复码只允许重绑，不能直接取得完整业务会话。
- 员工角色与启停由配置维护；权限变化撤销旧会话，维护角色不自动拥有商户业务或付款权限。
- 商户采用平台 UUID 和独立展示编号，资料版本保留历史，不把供应商字段写入商户主表。
- WebAuthn 用于登记与个人凭证验签试验；本日验证不能替代 D6 的订单快照签名和执行校验。

## 权限与恢复边界

固定角色为运营、财务、主管、EO、Admin、Root。运营负责商户建档和资料维护；维护角色不默认拥有业务读写权限。人员与审批阈值继续保持配置能力，具体人员不写死。

在更细的管理授权规则确认前，员工管理接口仅允许 Root；禁止自改角色和启停，敏感变更须再次 TOTP。人工遗失重置流程保持关闭，不能通过后台直接清除 2FA。初始 Root 通过空库 bootstrap 命令建立并完成本人 TOTP 登记，不提供默认账号密码。一次性恢复码是当前可用的基本恢复路径。

## 通道门槛

沿用 Day1 的证据缺口：USD 权限、数币网络、P2A 对端到账、反向资金路径及银行出款均未新增已验证证据。相关动作不纳入本日可用能力。此前 Slash 调研也没有证实客户资金模型和 on-ramp 能力，不能据此替换现有通道。

正式沙盒采用 `/kaloq-v1/` 入口、`kaloq-v1` 服务、127.0.0.1:4102 和独立 `kaloq_v1_sandbox` 数据库。旧 Demo 保持原有服务和数据库，用作通道参考。这是落实正式目录隔离的部署选择；正式阶段发布使用 `v1.0/scripts/deploy-sandbox.sh`，不能误用根目录旧 Demo 脚本。

迁移由专用身份执行；运行身份只获得所需表权限。应用回滚切回上一发布目录，保留已写入的身份、商户和审计数据；本日不提供破坏性 down migration。

## 线上验收方法

入口：**https://v-2077.com/kaloq-v1/**。发布版本 `20261105T040121Z`，独立服务 `kaloq-v1`，运行身份与迁移身份分别为 `kaloq-v1` 和 `kaloq-v1-migrate`。

1. 初始账号为 `owner`。随机密码保存在本机仓库 `secrets/formal-v1/bootstrap.json`，未写入 Git。账号当前无有效会话、未绑定认证器。
2. 首次登录，用本人 Google Authenticator 扫码绑定，保存一次性恢复码。
3. 在员工与权限中创建运营账号，角色选“运营”。保存时需要一个尚未用过的动态码；上一动态码刚被用过时等待下一轮。
4. 使用运营账号登录并绑定认证器，即可查看全部商户、建档、编辑资料、搜索及进入商户工作台。
5. 在个人安全页登记电脑或手机凭证并点击“验证凭证可用性”。目前验证不批准任何资金业务；请反馈真实设备/浏览器结果。

Root 用于维护员工，商户办理入口属于运营。商户初始状态为“待完善”；状态变更不会触发供应商开户。界面上的订单、资金等服务明确显示尚未开放。

公网健康接口返回 200；实际密码→TOTP→完整会话→受限恢复流程通过。运行角色下查询员工/签名凭证及创建登记挑战通过，Root 访问商户返回 403，密码挑战访问员工返回 401；恢复后未完成重新绑定仍为 401。详见 [远端登录验证](evidence/remote-login.json)。公网 Chrome 登录页与移动布局结果见 [浏览器记录](evidence/public-browser.json)。

## 发布和本地复查

- 首次基础配置：将 `scripts/provision-sandbox.sh` 通过 SSH 在指定测试服务器执行，建立专用身份、空库和受保护环境文件。
- 后续发布：在 v1.0 运行 `bash scripts/deploy-sandbox.sh`；脚本构建独立源、创建不可复用 release 目录、备份数据库、迁移、授权运行账号、切换服务并检查健康，然后验证 Nginx 再装入独立路由。服务/路由启动失败时回切上个应用目录；数据库新增结构保留。
- 前端/API 启动方式见各自 README；使用 `scripts/with-toolchain.py` 固定开发机工具版本。
- `scripts/check-browser.mjs` 是一次性空身份测试库的 Chrome 流程验收。凭证文件由测试环境生成，PLAYWRIGHT_MODULE 指向测试依赖；不要对已有员工运行。
- `scripts/check-remote-login.py` 仅在空库 bootstrap 后验证未绑定的初始 owner，并通过一次性恢复流程回到待绑定状态；不能用于已在用的账号。
- `scripts/check-session-expiry.mjs` 用受控 HTTP 响应验证前端会话撤销时清除受保护界面。
