# Kaloq 内部版页面清单

> 2026-11-04 范围更新：沙盒 HKD 样例、正式 USD；角色人员、EO 门槛和测试款采用可更新配置；个人签名支持电脑和手机；平台收费留待单独需求。通道实际扣款、到账及扣费随回执记录核对。详见 [D1 确认与决策登记](day-01/decisions-and-readiness.md)，本说明优先于下文相冲突的旧建议。

> 第一版页面规划草案。依据内部版功能树及本轮确认整理，供产品、设计、开发评审；页面数量不代表已开发数量或工期承诺。

## 1. 已确认的入口与使用方式

这一版只面向内部员工。运营登录后看到全部商户列表，可以创建商户档案；进入某个商户后，围绕该商户办理服务。商户通过群等线下渠道传达需求和确认，由运营代录并保存相应凭证。

- 商户是业务服务对象，本期不创建商户登录账号，不做商户自助注册、登录或工作台。
- “创建商户档案”保存主体、联系人等信息，并生成唯一 Kaloq 商户 ID；与供应商 KYC/KYB 开户分别处理。
- 运营首页就是商户列表，不再额外增加一个重复的首页仪表盘。
- 商户服务工作台是日常操作中心。资料、开户、收付款、订单和账本均绑定当前商户；从商户入口新建业务自动带入商户身份。
- 财务、主管、EO 使用本人审批中心；Admin、Root 使用授权维护页面。这些均为内部员工角色。
- 运营可见全部商户列表；资料字段、资金明细和操作权限另行控制。“全部商户可见”不意味着能看其他员工的专属审批。

主要路径：**登录 → 商户列表 → 某商户服务工作台 → 选择服务 → 创建订单/提交申请 → 等待审批 → 查看执行和到账 → 对账结单**。

已确认：商户工作台内有该商户的订单列表，每笔订单可查看状态；进入订单详情可查看整条业务流程（Pipeline）、当前环节、卡住原因及后续处理入口。这里的“商户页”由内部员工使用。

全部页面与主要跳转见 [Mermaid 页面关系图](internal-v1-page-map.md)。

## 2. 页面数量与计算口径

当前建议 **35 种页面模板**，分为下列 8 组。数量按独立业务视图计算，不按商户数量、URL 数量或功能树节点数计算。

| 分组 | 数量 | 页面 |
|---|---:|---|
| 登录与个人安全 | 5 | 登录、登录二次验证、首次绑定、账号恢复、我的安全设置 |
| 商户服务 | 4 | 商户列表首页、创建/编辑档案、商户服务工作台、KYC/KYB 资料表 |
| 订单与运营 | 6 | 全部业务订单、创建/编辑订单、订单详情、资金申请、报价管理、业务异常中心 |
| 审批与消息 | 3 | 我的审批、审批详情、消息中心 |
| 资金与对账 | 6 | 入金核验、商户账本、总池账本、冻结与在途、对账工作台、对账差异详情 |
| 监控与审计 | 4 | 监控概览、告警中心、安全事件详情、审计日志 |
| 员工与业务设置 | 4 | 员工管理、角色与权限、审批路线、业务规则 |
| 通道与系统维护 | 3 | 通道管理、任务与回调、安全恢复申请 |
| **合计** | **35** | **内部员工使用的页面模板** |

计数规则：

1. 创建和编辑共用表单模板，算一页；新增、编辑、只读是不同状态。
2. 法转数、数转法共用订单模板，提供两套业务步骤和字段，不重复计数。
3. 同一商户详情里的银行账户、地址、VA 等标签页不单独计数，但其字段和交互仍需设计、开发。
4. 搜索筛选、确认弹窗、附件预览、2FA 验证框、签名提示不单独计页。
5. 列表中的轻量记录详情用抽屉；需要长时间核验、独立任务链接或复杂证据的审批、订单、差异、安全事件保留独立详情页。
6. 后台执行、验签、原子记账和通知重试是服务能力，不因没有独立页面而从开发范围中删除。

页面数在低保真原型评审后再冻结。下表的页面划分和未明确的角色操作权限为建议方案；已确认的个人审批隔离与运营全部商户列表必须保持。

| P35 | 安全恢复申请 | 获授权处理人员；维护导航/P29 | 员工认证器遗失、账号恢复、签名凭证重绑申请；身份核验材料、处理状态和受控操作记录；需审批时进入 P17。Root 自身紧急恢复另定离线方案，不能设计成自批按钮 | — |

### 4.1 订单详情中的流程进度 Pipeline

P12 顶部显示整体状态、当前环节、进入该环节的时间、停留时长、最新查询时间，以及当前等待事项或阻断原因。下面展示完整业务流程，点击环节查看该阶段子单、证据、状态变更记录和获授权的处理入口。业务流程与资金分录分别展示，可互相跳转。

法币转数币的示意阶段：业务建单 → 入金核验 → 划转/P2A 申请与审批 → Pyvio 划转及 P2A 执行 → Actyve 到账核验 → 测试付款（适用时）→ 正式付款申请与审批 → Actyve 出款 → 商户到账确认 → 对账结单。

数币转法币的示意阶段：业务建单及报价确认 → 收款地址/收 U → 入金核验与归集 → A2P 申请与审批 → A2P 执行 → Pyvio 主账户到账 → 子账户分发 → 银行付款申请与审批 → Pyvio 出款 → 商户到账确认 → 对账结单。

每个阶段内部可展开执行子步骤；未适用步骤显示“不适用”及原因。上述是页面展示模型，审批合并方式、测试规则和通道能力仍按最终业务规则执行。

| 界面内容 | 展示要求 |
|---|---|
| 环节状态 | 未开始、等待、处理中、已完成、不适用、失败、结果未知、已阻断；除颜色外显示文字/图标 |
| 时间 | 进入、完成、最近更新和停留时长；超时阈值来自配置，普通等待不直接标为失败 |
| 卡点 | 显示具体原因，如“等待财务审批”“来源已扣、目标到账待核实”“测试款尚未确认”“报价已过期”“执行校验未通过” |
| 下一步 | 展示负责岗位/处理队列，以及当前用户可用的补资料、查原单、重新报价、申请复核、查看异常等入口；无操作权时显示等待事项 |
| 证据 | 来源/目标通道、子单号、回执、入账及账本关联；通道最新状态与本地流程状态分开显示，查询失败提示数据可能滞后 |
| 审批隐私 | 对非指定审批人仅显示审批环节及是否满足条件，不展示他人的审批人身份、意见、附件或个人签名记录；只有本人的审批可跳 P17 |
| 版本与重试 | 历史申请版本、重试和重新审批记录可追溯；不得把已失效版本标为当前通过，结果未知不提供直接重复付款入口 |
| 更新 | 后台状态变化后及时刷新，提供手动刷新；通知、轮询或推送方式由实现选择；刷新不创建新的付款任务 |

例如：“当前停在 Actyve 到账核验，Pyvio 已扣款，目标到账尚未匹配，已等待 18 分钟”，并提供“查询原单”和“查看异常”入口。时长是示意值，不能据此假设通道超时。

商户订单列表和 Pipeline 分别属于 P08 和 P12，**不增加独立页面，模板总数仍为 35**。

## 6. 页面状态与权限设计要求

所有列表都需要：首次无数据、搜索无结果、加载中、加载失败、分页、无权访问。敏感导出按当前人员权限生成，不通过后台全量导出扩大权限。

资料/表单需要：草稿、字段错误、保存中、提交中、提交失败、已提交只读、版本过期、待确认、待审核、补件、驳回及重新提交。

资金页面需要：余额不足、冻结失败、等待审批、已批准待执行、执行中、结果未知、部分成功、明确失败、安全阻断、已扣未到、到账待确认、待对账、已结单。业务、审批、资金和通道状态分别展示。

审批页面需要：本人的待处理、已处理、申请作废、版本变化、凭证失效和无权访问。隐藏按钮之外，还要对数据、附件、计数、搜索、导出及操作做服务端鉴权。

## 8. 建议的原型顺序

首先画一条运营主路径：P06 商户列表 → P07 建档 → P08 商户服务工作台 → P09 补资料 → P11 建业务单 → P12 查看订单 → P13 提交资金申请。

其次接上审批：P06 的本人提示/P18 消息 → P16 我的审批 → P17 核对并签署 → P12 等待执行和查看结果。用两名同角色审批人的原型状态展示个人隔离。

再接账务闭环：P19 入金核验 → P20/P21 账本 → P22 冻结与在途 → P23 对账 → P24 差异处理 → P12 结单。

随后画安全阻断分支：P17 已批准 → 执行前发现不一致 → P26/P27 告警调查，相关订单保持阻断。最后补账号恢复、配置和系统维护页面。

每页原型需标出进入方式、离开方式、使用角色、字段、操作、异常状态和数据来源。页面清单评审通过后，再按页面与后台能力共同拆任务和估工期。

## 9. 仍需确认但不阻碍绘制主流程的事项

| 事项 | 对页面的影响 |
|---|---|
| 内部版是否纳入独立法币付款等旧商户版能力 | 当前主服务按钮按法转数/数转法；新增服务可复用订单模板，但应单独明确字段、规则和通道能力 |
| 各岗位可看的敏感数据、操作与维护权限 | 运营全部商户列表已确认；P20–P35 的敏感明细和按钮权限需逐项定稿 |
| 审批拒绝后终止还是退回、替岗和兼任规则 | 决定 P12/P16/P17/P31 的状态、按钮和后续路径 |
| 付款自动执行还是还要人工执行确认 | 当前按审批后受控后台执行规划；若增加人工执行，需授权角色和操作步骤 |
| 大额、费用预留、测试与冻结释放规则 | 决定 P13/P17/P22/P32 的字段、提示和校验 |
| 审批人的个人签名设备方案 | 决定 P05/P17/P35 的绑定、签名和恢复交互 |
| 群内确认、邮件或其他凭证的有效条件 | 平台由运营代录已确认；资料审核和上游开户接受何种凭证仍需定稿 |
| 签名异常的接收人、离线通知及升级时间 | 决定 P18/P26/P27/P32 的通知设置；站内通知不足以保证未登录时即时触达 |
