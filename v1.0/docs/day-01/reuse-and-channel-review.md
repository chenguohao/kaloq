## 3. 需要在迁入前修正的具体缺口

1. `money.FeeBps` 使用 `int64` 直接乘法，`Convert` 对未知资产和 `big.Int` 转 `int64` 缺少失败返回；金额工具迁入前应补边界处理。当前发现来自代码审查，未在本次执行数值测试。
2. `jobs.go` 将运行超过五分钟的任务重新置为 pending，完成更新仅按任务 ID，缺少领取代次校验。正式版要阻止旧执行者迟到结果覆盖后续领取状态，并按动作协议处理提交后崩溃的未知结果。
3. `jobTxSubmit` 调用供应商前只检查 pending，未建立审批等待和持久化的提交尝试。提交成功但本地回写失败后，应先查原单，不能将任务重试直接解释为再次付款。
4. `failTx` 按整笔本金与费用释放，正式多阶段订单必须按已经确认未扣或已退回的金额处理。来源扣款、目标未到和费用已发生需单独记录。
5. Core 的 Provider 是单一字段，回调去重以供应商品牌名为范围。正式版需实例范围与账户范围，允许同品牌多个签约账号。
6. `sandbox.go` 使用进程内 mutex 和文件 rename 保存 Demo 状态。正式资金记录需要数据库事务、跨进程一致性和可靠任务，文件状态不作为正式账务唯一来源。
7. 现有迁移器按文件名判断是否已执行，缺少迁移锁和内容校验。正式迁移启动前需补齐，并与业务应用启动解耦。
