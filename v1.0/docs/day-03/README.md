# Day3 商户业务单与阶段进度

2026-11-06 已发布至[正式开发沙盒](https://v-2077.com/kaloq-v1/)。本日可验收双向业务受理、原始指令与报价版本、商户收款目标、通道资料和订单进度。资金冻结按 D4 排期，审批签名和真实执行受 D5–D6 门槛约束。

## 在工作台验收

1. 使用已绑定认证器的**运营**账号登录，进入「商户工作台」并选择一个商户。初始 owner 可在「员工与权限」创建运营账号。
2. 打开「资料与收款目标」。有开户或 VA 回执时登记服务商实例、原账号归属和凭证引用。VA 关联同一实例下本商户的开户记录。银行账户或链上地址也在此登记，修改会生成目标新版本。
3. 在「业务订单」点击「创建订单」，选择法币转数币或数币转法币，填写来源金额和客户原始指令。取得报价后可一并录入汇率、到账金额、有效期和凭证依据。建单允许先登记指令再补资料。
4. 保存后查看「当前环节」「当前卡点」和「下一步」。向下可查看当前版本的资料、报价和计划执行子单。沙盒以 **HKD / USDT** 受理，正式环境法币配置为 **USD**。订单固定受理时的法币。
5. 点击「修订订单」保存 V2，再切回 V1 查看原金额、原指令和当时的目标与实例。响应丢失时点击「重试原请求」，系统按原请求号返回同一结果。

## 关联现有开户与 VA 记录

正式档案直接使用所选商户的 Day2 资料版本。旧 Demo 的开户与 VA 使用按用户、按实例的显式映射。上线时未导入实际客户资料。业务方核定旧用户、正式商户和签约账户的对应关系后，可以在页面登记，或对一份受控 Demo 状态导出运行单条关联工具。

从仓库根目录执行下列命令。替换示例参数，先运行离线预检。加上 --apply 后工具会提示输入运营账号、密码及动态码，从接口读取正式商户编号与当前资料版本，核对通过后才写入。

```sh
python3 v1.0/scripts/link-demo-evidence.py /path/to/controlled-demo-state.json \
  --user-id OLD_USER_ID --merchant-id FORMAL_MERCHANT_UUID \
  --merchant-code FORMAL_MERCHANT_CODE --profile-version 1 \
  --instance pyvio-sandbox-account-a --account-scope ORIGINAL_UPSTREAM_SCOPE \
  --include-va
```

开户使用所选用户的 unit_id。VA 使用该用户的 flow.ga_id，以 va_data 回执币种为准，核对 VA 标识、回执提供的 Unit 和申请币种。回执不足时可去掉 --include-va 只登记开户。工具把必要标识与来源摘要送到平台 API，完整状态文件留在原位置。请保留原始凭证以便复核。两条关联分别提交，若后一条失败，修正原因后可重试，完全相同的已有记录会被复用。
