# D3 数据与执行设计评审

2026-11-06。订单受理、渠道资料和目标版本采用 003、004 两份增量迁移。资金模型另附可在验收库内执行并回滚的 SQL 草案，D4 实施前按以下决策复核。[SQL 草案](funds-design-review.sql)

| 场景 | 已定技术边界 | 后续放行条件 |
|---|---|---|
| 相同能力接第二家服务商 | 商户 UUID 和订单编号独立于服务商；实例代码在环境内唯一。外部资源按实例、类别、上游账号作用域和外部标识去重；VA 固定所属开户记录。新增实例通过新增记录接入。 | D13–D14 验证双实例故障隔离、重启恢复和已发出请求的查单。 |
| 订单修订 | 商户、订单版本、档案版本、目标版本和渠道资料有外键。原始指令、报价、计划和阶段按订单版本保存；新版本替换当前指针。 | D5 之后已提交审批的快照变化须重新申请，既有审批证据留存。 |
| 金额与扣费 | 受理金额使用正十进制字符串，沙盒 HKD 与正式 USD 精度 2、USDT 受理精度 6，最小单位为 38 位整数。执行前按获准网络、合约及资产定义确定精度。按资产和实际来源资金位置分别授权扣款上限。 | 通道费以报价和实际回执核对。EO 门槛、测试款和包含在主款内的规则均要固定配置版本。 |
| 资金位置与预占 | 平台池和商户在池内的归属分别保存；余额键含归属、位置、资产和桶。受控记账过程按固定键序锁头寸，条件扣可用、增占用，写流水、过账去重键与序号在同一事务完成。 | D4 运行账号只获指定记账过程执行权；过程对每项资产分组汇总分录，至少两行且和为零。独立延迟约束触发器在事务结束时复核平衡。测试并发、重试、单行失败整体回滚。 |
| 快照与签名 | 服务端按带版本的规范编码生成快照，绑定商户、订单版本、指定人员、报价、资产、测试规则、实例、来源和完整目标。签名挑战绑定用途、快照摘要和员工。 | D6 按原快照逐字段比对最终请求，复查员工、凭证撤销和通道暂停。规则或人员缺失时停在待配置。 |
| 投递与恢复 | 执行记录固定原实例、账号和长期请求号；任务租约增加代次，陈旧租约不能提交结果。超时保留占用，向原实例查单。回调去重与业务过账唯一键分别建表。 | D6/D9 验证超时、崩溃、部分成功、重复与乱序。新实例停用时仍需为旧单保留查单、回调和对账。 |

D3 接受运营登记的原始指令文本。登记通道开户或 VA 只建立待复核关系，真实归属、开户资格、入账证据需由业务人员核验。旧 Demo 的整份状态留在原仓库或受控导出位置，仅在指定用户与正式商户已经核对后使用映射工具。

资金路径、精度与回执的开放条件沿用 [D1 设计](../day-01/data-and-workflow-design.md) 及[开发基线](../development-baseline.md)。SQL 草案验证关系和键的可建性。资金账务的行为验证分别在 D4–D6、D9 和 D11 留证。
