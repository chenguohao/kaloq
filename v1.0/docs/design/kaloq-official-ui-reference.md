## 2. 视觉方向（官网实测）

整体是偏自然、克制的金融品牌风格：**暖米白背景 + 深森林绿文字与深色区块 + 少量荧光黄绿强调**。英文大标题采用细长衬线字，正文、导航与操作文字采用无衬线字。模块留白较大，卡片边角柔和，装饰集中在产品示意图和品牌首屏。

首页首屏是橄榄色山丘、门框与暖金色田野的动态场景；白色主标题居中，重点词用黄绿色斜体。产品页更侧重深绿色背景、卡片或账户 UI 示意。后续支付页可继承色彩、字体层次与卡片感，交易表单区域保持平静、易读。

Logo 为小写 kaloq 字标，尾部有黄绿色圆点；深背景使用浅色 Logo。实测首屏图片来源为站点的 `/images/kaloq-logo-light.png`（通过 Next 图片接口输出）。正式开发优先获取原始品牌资产，不手绘替代字标，不依赖官网图片代理作为生产资源。

## 3. 布局与页面模块（官网实测）

首页模块顺序：顶部品牌导航 → 动态首屏 → 四项能力卡片 → 三步开卡介绍 → 使用场景轮播 → 信任指标区 → 联系 CTA → 多列页脚。

- 桌面导航高约 **65 px**：左 Logo，中间 Products / Solutions（切换语言后也观察到 Use cases）/ Pricing，右侧语言胶囊。导航在滚动后的截图中仍位于顶部。
- Products 点击展开后显示两项产品，每项为名称 + 一行解释；使用 menu/menuitem 语义。
- 能力区外边距实测为上下 **110 px**、左右 **32 px**；开卡步骤区上下 90 px；信任区上下 72 px。属于官网叙事留白，不适合作为支付表单的默认间距。
- 四张能力卡片两行交错宽度，桌面样本约 **526/339 px**、第二行反转，行内剩余间隔约 **22 px**；手机全部单列约 311 px。
- 能力卡片圆角 **20 px**，内边距 **30 px 32 px**；浅色半透明表面，柔和阴影，右上角圆形箭头。内部是账户、余额、转账和消费的缩略示意。
- 内容区大标题主要左对齐，首屏与结尾 CTA 居中；标题下接短说明，避免长段文字堆叠。
- 页脚采用深森林绿，品牌说明、产品、场景与法律信息分列；次级文字弱化，底部版权和社交入口。

## 5. 响应式与观察到的问题

390 px 视口下，导航折叠、能力卡片改单列，H1 变为 48 px，多行标题明显增加。实测 `document.documentElement.scrollWidth = 605`，大于 `innerWidth = 390`，存在横向溢出；桌面也记录到 scrollWidth 969、innerWidth 966 的小幅差异。尚未定位具体溢出元素，不能直接将该问题归因于某一组件。

英文初始语义内容与语言切换后部分内容不完全一致，底部 CTA 的 textContent 还包含中英文片段，而可访问结构只显示当前语言。本文以字体、色彩、组件层次为稳定参考，不将所有 DOM 文案原样复刻。

支付页面需要单独验收：320/375/390/768/1280 px 下不横向滚动，长地址可以换行或安全省略；手机键盘不遮挡当前字段；错误说明在原字段附近；提交按钮不覆盖费用明细。上述尺寸是建议验收范围，不是已测官网断点。

## 6. 后续支付页面的落地建议（尚未实现）

本节供下一步设计使用。现有内部版范围、审批和签名要求仍以开发基线和页面清单为准；不据此新增商户自助登录或绕过审批。本次「支付页面」暂按支付相关业务界面的视觉参考理解，最终是员工操作页还是客户收银台，实施前结合业务目标明确。

### 页面骨架

桌面建议采用米白底、简洁品牌顶栏，主体为左侧操作卡片、右侧订单摘要；手机改成单列，摘要可置于操作前，关键确认信息在提交前始终可见。建议主体最大宽度 1040–1120 px、两列间距 24 px、主卡 padding 24–32 px；手机外边距 16 px、卡片 padding 20 px。均为新的设计建议。

内容建议按「订单/收款对象 → 支付方式及账户 → 金额与费用 → 核对确认 → 结果/后续动作」分组。优先显示收款对象、支付/到账金额及币种、手续费、网络和汇率有效期（适用时）；不适用字段不凭空补默认值。

金额区建议 32–40 px 的 Inter 数字，资产代码独立显示；地址提供复制和完整查看，复制后给出文字反馈。输入框建议高 48 px、圆角 12 px、文字 16 px；主按钮建议高 48–52 px、深绿实底、白色文字。辅助按钮为浅底深绿字或描边，装饰黄绿只作局部点缀。

### 支付状态必须补齐

| 状态 | 界面应表达的内容 |
|---|---|
| 初始/编辑 | 可用方式、必填项、费用和可用余额（按实际业务） |
| 校验失败 | 字段附近说明原因，保留用户输入 |
| 报价过期 | 显示失效，重新获取后让用户核对新金额 |
| 提交中 | 清楚显示处理中，防重复点击 |
| 已提交/处理中 | 显示订单标识、进度和查询入口；不提前显示支付成功 |
| 结果未知 | 明示待确认，按原执行实例查单；不引导换通道重复支付 |
| 成功/失败/部分成功 | 根据确认回执显示金额与后续动作；部分成功独立呈现 |
| 未开放/无权限 | 解释限制，保持关闭；不能只有灰色按钮无说明 |

费用、限额、币种、网络、到账时效与角色权限都来自已确认配置/API。官网产品页和费用页的费用口径不同，且费用页明确为参考、待最终确认；本次不采纳其中任何费率为支付页面默认值。官网资质与托管宣传只记录其展示方式，不构成本项目的资质核验或可以直接复用的承诺。

## 7. 下一步使用方式与待确认事项

实施前仍需确认：页面使用者与入口、首期支付方式/币种/网络、费用和精度口径、是否需要二维码与倒计时、结果状态映射、品牌原始 Logo/字体资产及可用范围。此处是下一阶段输入，本次官网 UI 调研已完成，不将未确认项当作批准默认值。

本轮仅文档和公开网站证据：未变更数据库/API/任务/服务商绑定，未影响在途订单；无需数据库迁移、运行时检查或服务器部署。回滚可独立撤销本轮文档提交。
