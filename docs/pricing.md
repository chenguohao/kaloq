# 定价说明 · 通道怎么收 vs 我们怎么收

> 评估日期：2026-09-22。  
> **结论先说**：两家都不像 Stripe 那样挂一张公开价目表。能查到的多是营销口径；**真实批发价要向 BD 要合同**。我们对外也不该按「调一次 API 收多少钱」定价，而应按「动一笔钱收多少钱」。

---

## 1. 两家供应商现在能公开看到的定价

### 1.1 Pyvio（法币）

| 项目 | 公开说法 | 可靠程度 |
|------|----------|----------|
| 开户 / 账户管理 | 0 开户费、0 管理费 | 营销页常见，合同仍以商务为准 |
| 提现到国内银行 | 宣传 0 提现费，最快 T+0 | 同上 |
| 本地账户收款 | 手续费 **封顶 1%**（文章口径） | 有宣传数字，但未按国家/场景拆开 |
| 换汇 API | 文档写「换汇不收手续费」 | 通常意思是 **不加一笔显式手续费**；利润仍可能在汇率里 |
| 付款 | 无公开统一费率；API 有 `OUR` / `SHA`（银行链路谁承担中间行费用）、`pobo`（用自己 KYC 名义付款，另收费） | 付款价必须问商务 |
| API 接入本身 | 文档不收「按次调用费」 | 钱在资金动作上，不在 HTTP 请求上 |

出处（宣传，非合同）：

- https://pyvio.com/zh/products/collection  
- https://pyvio.com/zh/article/Local-account  
- https://docs.pyvio.com/pages/fx/

**对商务要问清的价目（至少）：**

1. Collection / B2B Collection / Direct Payment 各自费率（按币种、国家）  
2. Payout / Withdraw 按目标地区的固定费 + 比例费  
3. 结汇人民币：额度、费率、材料审核是否另计  
4. 收银台收单、湃付卡的费率  
5. 机构模式（子商户）有没有月费、最低流水、保证金  
6. 汇率：是中行牌价、还是加点；加点多少 bp  
7. **机构分成后台**（2026-10-03 商务口头：会开专用后台设加价；入账拆成通道费 + 我们分成 + 子商户余额）。要书面确认：何时扣、进哪个 Unit、通知字段、沙箱能否测、付款/换汇是否同样拆

### 1.2 Actyve（稳定币）· 2026-10-03 深挖公开材料

翻过：API 文档整包 JS（https://developer-doc.actyve.io，站点生成于 2026-07-06）、官网 https://actyve.io（几乎空白）、https://docs.actyve.io 与 https://actyve.com（打不开）。**没有任何公开价目表，也没有任何「机构分成 / 提价后台」页面或接口字段。**

文档侧边栏实际模块只有：Account、Payee、Chain Payee、FX、Withdraw、Deposit、Acquire、Notification、Report、File。  
**没有** Pyvio 那种 Create User、Unit、`X-Unit-Id`、内部 Transfer、customer_fee、markup。

能确定的收费形态只有这些：

| 出处 | 说明 | 是否给我们抽水 |
|------|------|----------------|
| 出金响应 `feeAmount` + `feeCurrency` | 示例数字是 **1**（单位随 `feeCurrency`，不是价目表）。备注只写 fee amount，没说是网络费还是平台费 | 这是 **Actyve 扣的**，不是 EOPay 的分成 |
| 换汇 `Query FX Rate` | 示例 `rate: 0.9985`（USDT→USD 约 15bp 点差量级）；有 `rate_id`、过期；错误码 `B_Outbound_RateExpiredError` | 点差归通道；**没有**「再加一层给我们」的字段 |
| `pobo=Y`（提到银行且用你们 KYC 当付款人） | 原文：*Pay an additional fee* | 额外费给 Actyve |
| 入金 Deposit | 通知字段是金额、链、tx，**没有 fee 字段** | 公开材料看不出入金服务费 |
| 官网 / 商户后台 | 无公开 portal（对比 Pyvio 的 business.pyvio.com） | **看不到抽水后台** |

Scope 文案里残留了 `transfer`、`global account`、`collection` 等和 Pyvio 一样的词，但 Actyve 文档 **没有对应接口**，不能当成已开通。

**结论：**

1. 他们怎么收费：公开可证的是 **出金扣费 + 换汇点差 + POBO 加价**；具体数字只跟商务合同。  
2. 有没有给我们抽水的后台：**公开文档和网站都没有。** 不能假定和 Pyvio 口头答应的分成后台是同一套。必须单独问 Actyve / 同一对接人。  
3. 在他们没开分账之前，EOPay 抽 U 只能：出金时自己少付、或我们账本记账后从客户 Actyve 余额转到我们主账户（后一种也要他们支持内部划转，公开 API 没有）。

问商务请直接用这三句：

1. 入金、链上出金、BankAccount、GlobalAccount 各自合同费率（含是否收网络费）  
2. 有没有机构/白标加价后台，入金能否像 Pyvio 那样拆成通道费 + 我们 + 客户  
3. 有没有子商户和内部划转；GlobalAccount 是不是 Pyvio 钱包

### 1.3 行业常识（两家都适用）

跨境 / 稳定币通道常见做法（BVNK 一类也类似）：

- **不公布标准价**，按客户量级谈  
- 显性收费：收款 %、付款固定费、链上网络费  
- 隐性收费：换汇 **点差（spread）**，往往比「手续费」更赚钱  
- API 调用本身通常免费，贵的是资金和换汇  

所以：**「他们的 API 怎么定价」≈「他们的资金动作怎么定价」**，不是按请求次数。

### 1.4 EOPay 对 U 收不收费（建议）

要收，但 **链上网络费必须单独写清、实报实销**，不要暗扣。

| 动作 | 建议 | 原因 |
|------|------|------|
| 入金（别人打 U 进来） | 0 或很低的 % | 发送方已经付了矿工费；入金再狠抽，合作方会去直连地址 |
| 出金（提到别人地址） | **固定费 + 少量 %**，另加网络费 | 出口收费站；和法币提现同一逻辑 |
| 划转换汇 | **汇率加点**（主利润） | 比按笔手续费厚 |
| 网络费（Tron 能量等） | 账单单独一行 | 客诉最多的就是「说好 1U 手续费，实际少了 2U」 |

Actyve 自己也会在出金里扣 `feeAmount`。对外报价 = 他们的费 + 网络费 + 我们的平台费。  
若他们没有入账分账，U 的平台费就做出金扣，或从客户 Actyve 余额划到我们的 Actyve 主账户（要问他们支不支持）。

## 2. 我们的聚合 API 应该怎么定价

### 2.1 先定原则

1. **向合作方收的钱 = 通道成本 + 我们的加成**（成本加成）。没谈到通道批发价之前，对外只能给「示意区间」，不能写死合同价。  
2. **按资金动作收费，不按 API 次数收费。** 查余额、查单可以免费或极低月费覆盖。  
3. **账单拆开写清**：通道成本（可透传或打包）+ 我们平台费 + 网络费（链上）+ 汇率（若有）。  
4. **第一期能力少，费率表也要少**：USD 收款、USDT 入金/出金、法币付款；别一上来按 20 个国家报价。

### 2.2 推荐的收费结构（给合作方）

| 收费项 | 怎么收 | 说明 |
|--------|--------|------|
| 平台费 · 收款 | 金额的 **x%**（可设最低/封顶） | 法币入账、稳定币入账都可收；或「只收出金、收款少收」吸引充值 |
| 平台费 · 付款 | **固定费 + y%** 或只固定费 | 小额怕被 % 打穿时用固定费；大额用 % |
| 汇率加点 | 在通道汇率上再加 **z bp** | 有兑付（USDT→USD / 法币换汇）时，这是主要利润来源之一 |
| 链上网络费 | **实报实销** 或「实报 + 小额服务费」 | 别把 gas 吃进自己口袋却不说明，客诉最多 |
| 月费 / 接入费 | 可选：月费覆盖查单、webhook、对账 | 流水大的客户可免月费、提高流水折扣 |
| 开户 / KYC | 可选：按通过客户收一次 | 覆盖人工与通道开户成本 |

**不建议**：按 HTTP 调用次数收费（难卖、也不符合支付习惯）。

### 2.3 三种卖法（选一种当主策略）

| 模式 | 合作方看到什么 | 适合 |
|------|----------------|------|
| **A. 打包价** | 「收款 0.8%，付款 $1 + 0.3%」一张表，里面已含通道 | 最好卖，我们吃差价也扛通道涨价风险 |
| **B. 成本透传 + 平台费** | 账单写：通道费 xx + 我们平台费 yy | 大客户、要审计的；我们利润更干净 |
| **C. 只赚汇差** | 手续费极低，汇率稍差一点 | 换汇/兑付量大的场景 |

第一期建议：**A 或 B**。稳定币↔法币一开通，就一定要单独定 **汇率加点**，不要假装「换汇免费」。

### 2.4 示意数字（仅供内部讨论，不是对外报价）

假设将来谈下来的通道成本大概是这个量级（**虚构，用来想结构**）：

| 动作 | 通道成本（示意） | 我们对外（示意） | 我们毛利（示意） |
|------|------------------|------------------|------------------|
| 法币收款 | 0.3%–1% | 通道 + 0.1%–0.3% | 10–30 bp |
| 法币付款 | $0.5–$5 + 少量 % | 再加 $0.2–$1 或 +0.1% | 按笔 |
| USDT 链上出金 | 网络费 + 平台费 | 实报网络费 + 我们 $0.1–$0.5 | 按笔 |
| USDT→USD | 通道点差 10–30 bp | 再加 5–20 bp | 点差差价 |

真实数字必须等 Pyvio / Actyve 商务报价填进表后，才能对外。

### 2.5 定价时要防的坑

1. **只看「手续费」、不问汇率** —— 点差可能比手续费贵。  
2. **收款便宜、出金很贵** —— 合作方会投诉「钱进来容易出去难」。  
3. **小额被固定费打穿** —— 设最低金额，或小额用更高 %、取消固定费。  
4. **我们打包价，通道突然涨价** —— 合同留「通道成本变动可调」或改用透传模式。  
5. **子商户模式** —— 若合作方再卖给下游，要约定：我们只向合作方收一层，还是允许他们加价（类似 BVNK 的 customer fee / Stripe Connect application fee）。

## 3. 马上要做的事（商务，不是研发）

向 Pyvio、Actyve 各要一份 **API / 机构合作费率表**，至少覆盖：

1. 收款、付款、换汇/兑付、链上网络费  
2. 月费、最低流水、保证金  
3. 沙箱是否与生产同价结构  
4. 是否允许我们在账单上对终端加价（白标加价）—— **Pyvio 商务口头已答应专用提价/分成后台，待合同和沙箱验证**  
5. Actyve `GlobalAccount` 是否打进 Pyvio，以及这条链路的费率  
6. 入账拆分顺序：先扣谁的、失败退回时分成退不退、我们的分成进哪个 Unit

没有这张表，对外定价只能停在「结构」，不能停在「数字」。

## 4. Pyvio 机构分成（2026-10-03 口头，待书面）

商务反馈：会开通**专用后台**做提价和分成。VA 收到款后，类似 Layer1：

```text
用户打 100 进 VA
        ↓
Pyvio 通道费（平台/通道一部分）
我们的分成（后台设的加价）
剩余 → 子商户自己的钱包
```

公开 API 里仍然**没有** `customer_fee` 这类字段，分成应是他们账本在入账时做的，我们主要是：后台改费率 + webhook 里核对拆分金额。

落地前至少拿到：

1. 合同或邮件写明「入账自动分成」，不只是后台能看报表  
2. 沙箱走一笔，看子商户 `net_amount`、我们账户入账、通知字段是否对得上  
3. 付款、换汇是否同样拆；退款/入账失败分成怎么回冲  
4. 我们的分成进哪个 Unit，能不能提到对公户  

未验证前，研发仍按「入账全额进子商户、我们另记账」做兼容，验证后再把对外可用余额改成通道拆完后的净额。
