# Kaloq V1

本目录是交给产品、工程团队或 AI 编码代理的 **V1 唯一需求入口**。

先读本页的简版范围，再读[详细需求与架构](detailed-requirements.md)。详细版包含页面验收、开户/KYC 资料保存、业务边界、架构图、开发顺序、通道待确认项和上线验收。根目录的旧版 Pyvio + Actyve 研究资料仅作历史背景；遇到范围冲突，以本目录为准。

## 一眼看懂 V1

| 模块 | V1 功能 |
|---|---|
| 主页 | 资产总览；最近交易记录快捷入口 |
| 账户 | 未开户时发起开户及 Pyvio KYC/KYB；加密保存用户提交的资料快照和附件，后续可预填复用；已开户时查看 VA、关联钱包及余额 |
| 收钱 Recv | 收钱指引/消息、到账状态和收款记录 |
| 转账 Sent | 法币转法币；数字资产转数字资产 |
| 自有账户划转 | 商户自己的法币钱包转 USDT；自己的 USDT 钱包转法币 |
| 记录 | 收钱、Sent 转账、自有账户划转的统一交易明细 |
| Settings | 成员管理及预设角色选择 |
| Kaloq API 与 API 文档 | 网页和接入方均调用 Kaloq API；Kaloq 后端封装 Pyvio；提供面向接入方的 Kaloq API 文档 |

## 边界

- 首期商户：一家乌兹别克斯坦企业；目标法币为 UZS，数字资产暂定 USDT。
- 首期 Provider：只接 Pyvio。KYC/KYB、收付款和兑换由 Pyvio 执行；平台负责统一 API、工作台、交易状态和运营账本。
- Sent 表示向外部目标付款/转账；自有账户划转只表示商户自己法币钱包与数字钱包之间的转换/移动。两者不能混为一个“转账”类型。
- 每个 VA 与 Pyvio 数字账户的配对按已沟通模式设计，需在沙盒确认实际 API 字段、账户余额位置、可用网络与交易能力。
- 用户资料快照仅在已授权的用途内加密保留和复用。资料过期或主体信息变化时要求重新确认。
- 不假设任意币种、网络、第三方目标或四条资金路径都已获 Pyvio 开通；实现前用通道能力矩阵确认，未确认的能力不得显示为可用。
- 对外 API 隔离 Pyvio 字段和 ID，按稳定业务资源建模；增加 Provider 时不要求客户修改现有 API。
- 网页前端只调用 Kaloq API；Kaloq 服务端通过 Provider Adapter 调 Pyvio。网页发布 Kaloq 自己的 API 文档，包含认证、请求/响应、错误、幂等、回调和示例，不把 Pyvio 文档当作我们的 API 文档。

## 建议交给编码代理的阅读顺序

1. 本页：产品范围和硬边界。
2. [详细需求与架构](detailed-requirements.md)：页面、验收、数据、状态、架构和开发任务。
3. [通用程序架构](../program-architecture.md)：理解 Provider 抽象与模块边界；若与本 V1 范围冲突，以本目录为准。

编码代理开始实现前，应先输出 Kaloq OpenAPI 契约草案、Pyvio 能力缺口清单和需要沙盒验证的假设，尤其是 UZS 收款、VA/数字账户关系、Sent 两类路径、自有账户兑换、KYC 资料更新/复用。接口能力未确认时先完成稳定平台契约和 Fake Provider，不要臆造 Pyvio 字段或开放未确认资金路径。
