# 市场机会 · 乌兹别克斯坦跨境支付

> 来源：甲方 2026-09-27 提供的四个切入点，逐条核对了公开资料。  
> 结论先行：**最适合我们的是 D 数字资产 + C 汇款走廊，用 A 金融中心当公司落地的壳；B 教法合规先不碰。**

## 2. 逐条看：和我们有多近

| 编号 | 用大白话说是什么生意 | 和我们现有方案的距离 | 难点 |
|------|----------------------|----------------------|------|
| A | 在 TIFC 注册公司，做「中国—中亚—欧洲」贸易货款的中转结算 | 中。Pyvio 的 B2B 收款、结汇人民币对中国出口商这一端有用 | 要拿 TIFC 金融服务局的牌照，要有当地银行和代理行关系 |
| B | 给海湾资本提供符合伊斯兰教法的支付 / 清算 | **远**。教法主要管融资结构（不能收利息），单纯付款本来就不涉及利息，卖点不大 | 要教法委员会、懂伊斯兰金融的人；稳定币是否合教法各派说法不一 |
| C | 在外打工的乌兹别克人把钱汇回家 | 中。我们能做「收钱 → 换成稳定币 → 到乌兹别克兑成苏姆」 | 汇款**大头来自俄罗斯**，涉及制裁，Pyvio / Actyve 很可能不接；到账端要接当地卡组织（Humo / Uzcard）；这个市场利润薄、对手多 |
| D | 进 NAPP 稳定币沙盒，做稳定币跨境结算 | **最近**。Actyve 那一半本来就是稳定币出入金 | 要当地主体申请 NAPP 登记，央行批准；沙盒是试点，规模有上限 |

## 3. 建议怎么组合

- **D 当核心**：稳定币当桥，钱在链上跨境，两头各自兑成本地钱。这正好是 Actyve 能力 + 当地出入金。
- **C 当第一个场景**：汇款量大、需求真实，先挑**不涉及制裁**的来源国（韩国、土耳其、欧洲、海湾），不碰俄罗斯。
- **A 当落地的壳**：公司注册在 TIFC，享受税收优惠，也方便拿牌照。
- **B 暂缓**：等有具体海湾客户点名要时再说。

这也回答了之前「聚合成不成立」的疑问：我们的价值**不在把两家 API 翻译成一套**，而在**当地牌照 + 当地出入金**，这是客户自己找 Pyvio / Actyve 拿不到的。

## 4. 对现有方案的影响

| 影响 | 说明 |
|------|------|
| 通道要重新核实 | Pyvio 国家码表里有乌兹别克（UZ / UZS），但收单支持的币种里**没有 UZS**，官网也没宣传中亚。要问 BD 能不能付款到乌兹别克 |
| 要加当地通道 | 到账端要接能打到 Humo / Uzcard 卡的通道，候选见第 6 节 |
| 牌照前置 | 之前准备清单第 2 节「要不要牌照」，在这个方向下答案基本是**要**（NAPP 登记或 TIFC 牌照） |
| 第一期范围要改 | 原来的「USD + Tron USDT」要改成具体走廊，例如「某国 → 乌兹别克」 |

## 6. 能接的通道（Pyvio 不够时补哪些）

先说明乌兹别克的钱怎么到人手里：当地人主要用两种本地卡 **Humo** 和 **Uzcard**，汇款最后基本是「打到这两种卡上」。所以要找的就是能通过 API 打到这两种卡的通道。

### 6.1 海外 → 乌兹别克：付款到卡（汇款到账端）

| 通道 | 是谁 | 能做什么 | 要注意 |
|------|------|----------|--------|
| **Paysend Enterprise** | 英国的全球汇款公司 | 一个 API 直接付到 Humo / Uzcard，实时到账；有沙箱，官网写接入 8–12 周 | 服务持牌机构、汇款公司、金融科技平台（韩国的 Gmoneytrans 就在用）；**接入方自己要承担牌照和反洗钱责任**，见 6.6 |
| **Nium** | 新加坡的全球付款网络 | 付到乌兹别克的 SWIFT 银行账户；付到 UZS 的 Visa 卡 | 付到卡要额外经 Visa 审批；每张卡有日 / 周 / 月限额 |
| **Thunes** | 新加坡的全球付款网络 | 覆盖乌兹别克，包括现金取款 | 要找 BD 拿详细方式 |
| **Uzum Bank CrossBorder / Remit Core** | 乌兹别克本地银行 | 按卡号或手机号打款、查汇率、查状态、对账；接口文档公开 | 要和 Uzum 签协议；生产要走 IPSec 专线；每张卡单笔上限约 1875 万苏姆，30 天累计上限 9999 美元，每天最多 5 笔 |

入口：[Paysend 公告](https://paysend.com/en-ge/news/paysend-launches-payouts-humo-uzcard-cards)、[Nium 乌兹别克](https://playbook.nium.com/country/uzbekistan)、[Thunes 网络](https://www.thunes.com/direct-global-network/)、[Uzum 开发者文档](https://developer.uzumbank.uz/en/)

### 6.2 乌兹别克境内：收款（收单）

| 通道 | 能做什么 | 要注意 |
|------|----------|--------|
| **Multicard** | 一个 API 接 Visa、Mastercard、Uzcard、Humo，外加 Payme、Click、Uzum 等十来个当地钱包；有公开沙箱 | 本身就是当地的聚合商 |
| **Octo** | Visa / Mastercard / Uzcard / Humo 收款，有收银台链接 | |
| **Global Pay** | 5 种卡，包括银联 | 银联对中国方向有用 |

入口：[Multicard 文档](https://docs.multicard.uz/)、[Octo 文档](https://help.octo.uz/en/payment-via-web/one-stage.html)、[Global Pay](https://globalpay.uz/en/products/api-integration)

### 6.3 稳定币 ↔ 苏姆（NAPP 持牌）

| 通道 | 牌照 | 能做什么 | 要注意 |
|------|------|----------|--------|
| **Asterium** | NAPP 持牌（CE #0006、CD #0007） | 收 USDT 等加密资产，结算给商户美元或苏姆；有 API；可以打到个人 Humo 卡 | 注册页面要问「是不是乌兹别克居民」，外国公司能不能接要问 |
| **CityPay** | NAPP 持牌（CD #0004、CS #0012） | 合作方只收苏姆，加密资产操作全在 CityPay 那边；有 API | 同上 |

入口：[Asterium Pay](https://pay.asterium.uz/en)、[CityPay](https://citypay.uz/en?mode=business)、[NAPP 牌照登记册](https://napp.uz/en/pages/erlsp)

NAPP 登记册里有几家的牌照在 2026 年被**暂停了半年**，签约前要先在登记册上查对方当前状态。

### 6.4 聚合后的通道分工

| 资金动作 | 第一选择 | 备选 |
|----------|----------|------|
| 中国 / 海外收款（美元等） | Pyvio | |
| 稳定币收付（链上） | Actyve | |
| 付款到乌兹别克卡 | **Paysend**（海外公司就能签，接得最快） | Nium、Thunes；量大后直连 Uzum 更便宜 |
| 稳定币兑成苏姆 | Asterium 或 CityPay | |
| 乌兹别克境内收款 | Multicard | Octo、Global Pay |

**第一期建议只加一家：Paysend。** 这样就能跑通「海外收美元或 USDT → 付到乌兹别克 Humo / Uzcard 卡」这条汇款线，不需要先在乌兹别克有公司，但**需要我们自己有一张汇款类牌照**（见 6.6）。稳定币兑苏姆和境内收款，等有当地主体以后再接。

### 6.5 这些都要问 BD

1. 允不允许我们接入后包装成自己的 API 再卖（Paysend、Nium 本来就做这种生意，当地机构不一定）
2. 我们是外国公司，能不能直接签；要不要在资金来源国有汇款牌照
3. 资金来源国白名单，俄罗斯来源接不接
4. 费率、限额、预存备付金的要求

### 6.6 接入 Paysend 要什么

**技术上不难。** 官网写的流程是四步：接 API、配置走廊和币种 → 往结算账户**预存资金** → 发起付款 → 看状态回调。接口用 HMAC 签名，付款是异步的（`POST /processing` 下单，结果靠回调，回调头带 `X-OPP-Signature` 要验签）。和 Pyvio / Actyve 的套路一样，我们架构里的「通道适配 + 回调收件箱」直接能用。

**难在资质。** Paysend 官网原话：*Partners retain their own regulatory obligations under applicable AML, KYC and Licensing frameworks*，意思是它有它的牌照，但我们自己该有的牌照和反洗钱义务还得我们自己担。

我们的模式是「收别人的钱、替别人付到乌兹别克」，在绝大多数国家这就是**汇款业务**，要牌照。Paysend 会把我们当「金融机构」审核，要交：

| 类别 | 材料 |
|------|------|
| 公司 | 注册证明、公司章程、在公开登记册里「存续」的证明 |
| 人 | 至少 1 名董事、所有持股 25% 以上股东的护照；办公地址证明（3 个月内）；1 个月公司银行流水 |
| 牌照 | 当地央行或金融监管的登记；每个持牌国家的支付 / 汇款牌照 |
| 反洗钱 | 董事会任命的反洗钱负责人（MLRO）及其简历；董事会批准的反洗钱制度手册；员工反洗钱培训记录；最近一次独立审查（如有） |

公司在英国以外，授权书要做海牙认证（Apostille）。

**所以关键问题变成：我们用哪个公司、拿哪张牌照去签。** 几种路子：

| 路子 | 大概怎样 | 适合 |
|------|----------|------|
| 甲方已有牌照的公司去签 | 最快，材料现成 | 先问甲方有没有 |
| 在资金来源国申请汇款牌照 | 例如香港的金钱服务经营者牌照（MSO），相对便宜；英国、欧盟的电子货币牌照贵且慢 | 从哪国收钱就在哪国拿 |
| 在乌兹别克 TIFC 拿牌照 | 和甲方的「区域结算中枢」方向一致，还有税收优惠 | 长期方案，要等 TIFC 金融服务局开始发牌 |
| 用 Paysend Embed（在它的牌照下跑） | 官网写「在法律允许的地方」可以用它的牌照；但主要面向已持牌机构 | 要问 BD 我们能不能用 |

具体哪张牌照、要多久多少钱，要问律师。

### 6.7 Pyvio 和 Paysend 在资质上的差别

差别不在谁更宽松，而在**钱挂在谁名下**。

| | Pyvio 机构模式 | Paysend Enterprise |
|--|----------------|--------------------|
| 钱在谁名下 | 每个客户自己名下（Pyvio 给每个客户单独开 Unit） | 我们名下（我们预存资金，替客户付） |
| 谁做客户实名 | Pyvio 自己审（我们调 `Create User` 把客户资料报过去） | 我们做，Paysend 审我们 |
| 我们的角色 | 技术服务商，不经手客户的钱 | 汇款机构 |
| 我们要不要牌照 | 大概率不用，靠 Pyvio 的香港 MSO 牌照（No. 19-12-02927）；**要找 BD 书面确认** | 基本要 |
| 客户要交什么 | 大陆企业：营业执照；香港企业：CI、BR、NNC1、NAR1；海外企业：CI、章程、股权结构图 | 不直接交给 Paysend |

**但 Pyvio 解决不了乌兹别克：**

1. 不能付到 Humo / Uzcard 卡，收单币种里也没有苏姆。
2. 客户类型只有中国大陆个人 / 企业、香港企业、海外企业、越南个人 / 企业。**在外打工的乌兹别克个人不在里面**，所以做不了个人汇款。

**结论**：Pyvio 适合 B2B 那一头（中国出口商收海外货款），资质最轻，可以先做。付款到乌兹别克那一头，不管选哪家，都绕不开牌照问题。

## 7. 要问甲方的问题

1. 甲方在乌兹别克或其它国家有没有**公司、银行关系或支付 / 汇款牌照**？这决定我们是自己申请还是用甲方的主体去签通道。
2. 四条里甲方最想先做哪条？是有具体客户，还是看政策？
3. 汇款的来源国是哪里？是否包括俄罗斯？
4. 甲方和 NAPP / TIFC 有没有接触过？
